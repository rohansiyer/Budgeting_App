# Accessibility audit — v0.3 (Wave E3)

Scope: `src/screens/**`, `src/components/**`, `src/ducks/**` (accessibility-prop
and focus/hit-target fixes only, per handoff v3 §2.3 keep-rules). Excludes
`src/screens/settings/config.ts`, `SettingsScreen.tsx`, `HomeScreen.tsx`
(another agent's ownership — issues there are reported below, not fixed here).

## What was audited

1. Every `Pressable` / `TouchableOpacity` / `HardButton` call site under the
   owned trees, for a meaningful `accessibilityLabel` and a fitting
   `accessibilityRole`.
2. 48px minimum tap targets: keypad keys, category/recent-category squares,
   tab bar items, filter chips, picker rows, calendar cells, the pond's duck
   sprites.
3. Focus state on every raw `TextInput` outside the kit `Field` component
   (which already applies the tokens.focus treatment).
4. Color-never-alone: goal squares, meter warn/over states, the envelope
   ring, bills coverage caption.
5. Reduced motion: every `setInterval`/timed-animation site (`PondView`
   wander + ripple timers, `DuckSprite` stepped frames).
6. `accessibilityLiveRegion` / alert semantics on the undo Snackbar.

## Fixed in this pass

- **`src/ducks/PondView.tsx`** — duck sprites shrink to 32x28px at scale 2
  (flocks > 7 ducks), well under the 48px tap-target minimum. Added a
  computed symmetric `hitSlop` (no visual/layout change) so the touchable
  area reaches 48px regardless of flock size.
- **`src/screens/PondScreen.tsx`** and **`src/ducks/ResultsScreen.tsx`** —
  the "Name this duck" `TextInput` had no focus indicator (raw input, not
  the kit `Field`). Added local focus state + an accent border on focus,
  matching `Field.tsx`'s pattern exactly.
- **`src/screens/DailyDetailScreen.tsx`**:
  - `MoneyField` and the Edit-sheet "Note" `TextInput` had no focus
    indicator; added the same focus-border pattern.
  - The category-picker and income-source-picker rows (`pickerItem`) had no
    minimum height (content-sized, well under 48px); added `minHeight: 48`.
- **`src/ducks/ResultsScreen.tsx`** — the recap-insight `Pressable` (wraps
  `InsightRow`) relied on nested-accessible-node text aggregation instead of
  an explicit label; added an explicit `accessibilityLabel` built from the
  same prefix/amount/suffix the row already renders, so it can't be
  orphaned by future changes to `InsightRow`'s internals.
- **`src/screens/settings/SearchLedgerScreen.tsx`** — the "ALL" and
  per-category filter chips are a fixed 32px tall (below the 48px minimum).
  Added `hitSlop` (top/bottom 8, left/right 4 — matching the chip row's own
  gap so neighboring chips' expanded zones meet without overlapping).
- **`src/screens/settings/import/ImportReviewScreen.tsx`** — the
  accept/change/skip chips in the CSV review rows are 32px tall; added the
  same `hitSlop` treatment (row padding gives enough clearance from
  neighboring rows).

## Verified already compliant (no change needed)

- Kit components (`HardButton`, `ChoiceRow`, `Toggle`, `TabBar`, `CategoryChip`,
  `DuckChipSlot`, `EmptyState`, `InsightRow`, `BlockMeter`, `StepTrack`,
  `SparkBlocks`, `RuledList`, `PixelBox`, `Snackbar`) already carry correct
  roles/labels/states and 48px minimums.
- `Snackbar` already has `accessibilityRole="alert"` +
  `accessibilityLiveRegion="polite"` (item 6) — nothing to add.
- `DuckSprite` and `PondView` already gate every timer
  (`AccessibilityInfo.isReduceMotionEnabled` / `reduceMotionChanged`) behind
  `motion.reducedMotionRespect`, freezing to a static frame/pond under
  reduced motion (item 5). `Snackbar`'s dismiss timer is a one-shot, not an
  animation — explicitly out of scope per task brief.
- Color-never-alone: `GoalSquare`/`GoalRow` (Pond, Results, GoalStrip) pair
  every color square with an explicit met/missed or on-track/at-risk text
  label; `EnvelopeRing`'s color-coded arcs are backed by the Pond legend's
  per-category dollar text; `BillsScreen`'s coverage caption is a full
  sentence, color is decoration on top of it, not the only signal.
  `BlockMeter` exposes its state via `accessibilityValue.text` regardless of
  host caption.
- `AddExpenseSheet.tsx` keypad keys (48px), recent-category cells (48x48),
  and `PinPad.tsx` / `LockScreen.tsx` keypad keys (56px/64px) all already
  meet the minimum.
- `CategoryPickerSheet.tsx` picker rows already have `minHeight: 48`.

## Remaining (not fixed here — flagged for the owning agent/team)

- **`src/screens/HomeScreen.tsx`** (out of scope, owned by another agent):
  a raw "Amount to borrow" `TextInput` has no focus-border treatment (same
  gap this pass fixed in Pond/Results/DailyDetail); the day-bar chart
  columns (`barCol`) are narrow, similarly-sized Pressables that may also
  be under 48px depending on device width. Same fixes as applied elsewhere
  in this doc would close both.
- **`src/screens/CalendarScreen.tsx`** day cells: width is `14.2857%` of the
  screen with no gap between adjacent cells (only internal padding). On
  common device widths (~360-375px) this lands right at or just under 48px,
  and on narrower/older devices (~320px) noticeably under. Left unfixed
  deliberately: cells are edge-to-edge with zero gap, so a `hitSlop` here
  would make every cell's touch zone overlap its neighbors' by the full
  slop amount, risking consistent mis-taps at day boundaries rather than a
  clean fix. Needs an actual layout change (a small gap between cells, or a
  larger minimum column width) — out of this task's "no structural changes"
  scope. Flagged for the Pond/Calendar layout owner.
- **`src/providers/AppShell.tsx`** (out of scope): its own inline undo
  Snackbar already has `accessibilityLiveRegion="polite"` and a labeled,
  hit-slopped Undo button — no action needed, noted only for completeness
  since it duplicates the kit `Snackbar`'s behavior outside kit ownership.

## Tests

No new `.logic.ts` extraction was needed for this pass — every fix is a
pure JSX prop/style change (accessibilityLabel, hitSlop, minHeight, a
focus-state boolean already following the exact pattern proven by
`Field.logic.ts`/`Field.tsx`). Verification: `npx tsc --noEmit` clean;
full `npx jest` — 63 suites / 757 tests passed, no regressions.
